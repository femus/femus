# femus — PHP hardware framework. Дизайн v1

**Дата:** 2026-08-02
**Статус:** утверждён (брейншторм с владельцем проекта)
**Рабочее имя:** femus (по папке проекта, может быть переименован до публикации)

## 1. Цель и позиционирование

«Johnny-Five для PHP»: разработчик пишет обычный PHP на своей машине или на Raspberry Pi и управляет реальным железом — датчиками, реле, дисплеями, GSM-модемами. Один и тот же код без правок работает через два адаптера:

- **Firmata-адаптер** — PHP на любой машине (ноутбук, сервер, Pi), Arduino подключена по USB и исполняет команды по протоколу Firmata. Прошивка заливается один раз, дальше цикл разработки — просто перезапуск PHP-скрипта. Все микросекундные тайминги исполняет Arduino.
- **Linux-адаптер** — PHP работает прямо на одноплатнике (Raspberry Pi), датчики подключены к его пинам. Доступ через FFI: libgpiod (GPIO), i2c-dev (I2C), termios (serial). Автономный сценарий: Pi — самодостаточное устройство.

PHP **не исполняется на Arduino** и не компилируется в C — это осознанное решение (см. «Вычеркнуто»).

Ниша свободна: исследование экосистемы (08.2026) показало, что все заметные PHP-GPIO-библиотеки (PiPHP/GPIO 429★, ronanguilloux/php-gpio 267★) заброшены 5–7 лет назад и построены на sysfs, удалённом из современных ядер; Firmata-клиент Carica мёртв с 2019; FFI-биндингов к libgpiod не существует вовсе; зрелого AT/GSM-стека и аналога pyserial для PHP нет.

### Технологическая база

- PHP 8.2+, `declare(strict_types=1)`, `final` классы, интерфейсы-контракты
- Без обязательных C-расширений (FFI входит в стандартную поставку PHP)
- Framework-agnostic: без Laravel/Symfony-зависимостей в ядре
- Composer-пакет, открытый код

## 2. Слои архитектуры

```
Devices     Button, MotionSensor, Relay, Led, Buzzer, AnalogSensor,
            Lcd1602, Mpu6050, LoadCell, GsmModem, Camera (Linux-only)
               ↓ зависят только от контрактов
Contracts   DigitalPin, AnalogPin, PwmPin, I2cBus, SpiBus, Uart,
            Board (фабрика портов + декларация возможностей)
               ↓ реализуются адаптерами
Adapters    FirmataBoard (serial + StandardFirmata / ConfigurableFirmata)
            LinuxBoard   (FFI: libgpiod, i2c-dev, termios)
            FakeBoard    (эмулятор для тестов и CI — железо не нужно)
Runtime     Event loop: stream_select-реализация из коробки,
            LoopInterface — позже можно подключить Revolt/ReactPHP
```

Принципы:

- **Драйверы устройств не знают об адаптерах.** Драйвер получает в конструктор порты-контракты (`DigitalPin`, `I2cBus`…) и работает только с ними.
- **Capabilities.** Если устройству нужна поддержка со стороны прошивки (HX711), драйвер объявляет требуемую capability. FirmataBoard при её отсутствии даёт понятную ошибку («прошивка не поддерживает X, добавь модуль в ConfigurableFirmata»), LinuxBoard использует ядерный драйвер/FFI.
- **FakeBoard — часть ядра, не тестовая утилита.** Записанные байтовые диалоги (Firmata-пакеты, AT-транскрипты) позволяют разрабатывать и принимать pull request'ы без физического железа.

## 3. API-стиль

События + блокирующие шорткаты поверх одного event loop:

```php
$board = Board::firmata('/dev/ttyUSB0');   // или Board::linux() на Pi

$pir   = $board->motionSensor(pin: 4);
$scale = $board->loadCell(dout: 5, sck: 6);
$gsm   = $board->gsmModem('/dev/ttyUSB1');

// событийный стиль
$pir->onMotion(function () use ($scale, $gsm) {
    $gsm->sendSms('+7...', "Движение! Вес: {$scale->read()} г");
});
$board->run(); // event loop

// — или простой скрипт без лупа —
$pir->waitForMotion(timeout: 30);
echo $scale->read();
```

Внутри — однопоточный событийный ввод-вывод: `stream_select` на файловых дескрипторах (GPIO-события libgpiod, serial-порты). Многопоточность/Swoole не требуются: события датчиков — миллисекундного масштаба, микросекундные тайминги вынесены в Arduino/ядро/C-библиотеки. Swoole возможен позже как альтернативная реализация `LoopInterface`.

## 4. Состав v1 — вертикальный срез по всем классам устройств

Не «много датчиков», а по одному представителю каждого класса — так проверяются все интерфейсы сразу. Каждый класс нагружает своё: кнопки — прерывания и debounce; LCD — write-нагрузку I2C и init-последовательности; гироскоп — потоковое чтение регистров; аналоговые — опрос и масштабирование; HX711 — расширяемость прошивки; GSM — незапрошенные события и долгие команды.

| Класс | Устройства v1 | Arduino-путь | Pi-путь |
|---|---|---|---|
| Цифровой I/O | Button, MotionSensor (PIR), Relay, Led, Buzzer | StandardFirmata | libgpiod (FFI) |
| Аналоговый вход | AnalogSensor (уровень воды, фоторезистор) | встроенный АЦП | MCP3008 по SPI |
| I2C | Lcd1602 (PCF8574), Mpu6050 (GY-521) | Firmata I2C | i2c-dev (FFI) |
| Тайминго-критичные | LoadCell (HX711) | свой модуль ConfigurableFirmata (C++) | ядерный драйвер / FFI |
| UART / AT | GsmModem (SIM5216E): SMS туда-обратно, звонок, статус сети | — | termios (FFI) + USB-serial |
| Linux-only | Camera (V4L2): snapshot, start/stop записи | — | V4L2 через FFI/ffmpeg |

GSM-стек слоями: `Uart → AtChannel (очередь команд, таймауты, unsolicited-события вроде +CMTI) → GsmModem`.

Сквозной пример-витрина v1: **«PIR + камера + GSM: движение → запись видео → SMS»**.

## 5. Интеграция нового модуля

Новый драйвер = один класс против контрактов:

```php
final class UltrasonicSensor extends Device
{
    public function __construct(
        private DigitalPin $trigger,
        private DigitalPin $echo,
    ) {}

    public function onDistance(callable $fn): void { /* ... */ }
}
```

### Конвейер «фото → работающий модуль» (стандарт проекта)

1. **Идентификация** — маркировка платы/чипа по фото
2. **Datasheet** — пины, протокол, I2C-адрес, тайминги
3. **Схема подключения** — `docs/devices/<module>.md`: таблица «пин модуля → пин Arduino / пин Pi», предупреждения (3.3 В vs 5 В!)
4. **Драйвер + example** — `src/Device/...` + `examples/<module>.php`
5. **Проверка** — запуск с `--verbose`, отладка, запись в hardware-чеклист

## 6. Методика верификации: hardware-in-the-loop

### Замкнутые контуры — модули проверяют друг друга

| Контур | Передаёт | Принимает | Автотест |
|---|---|---|---|
| Радио 433 МГц | FS1000A TX | RX-модуль | отправили строку → приняли ту же |
| Свет | лазер / LED | фоторезистор | включили → уровень подскочил |
| ИК | IR emitter | IR receiver | послали код → декодировали тот же |
| Электрика | реле | цифровой вход (петля) | щёлкнули → вход сменил уровень |
| Вес | — | HX711 | эталонный груз |

### Инструменты

- **`femus test:hardware`** — интерактивный прогон: автоконтуры проверяются сами; где нужен человек, раннер ведёт по шагам («Подключи PIR к пину 4, помаши рукой → ✓»). Результат — отчёт: какие драйверы подтверждены на каком адаптере. Гоняется перед каждым релизом.
- **Стенд:** Raspberry Pi 4 + Arduino постоянно подключены по USB. Pi одновременно Linux-адаптер и хост Firmata-адаптера — обе платформы на одном столе. Радиомост 433 МГц (Arduino передаёт → Pi принимает) — живая демка обоих адаптеров.
- Верификация FM-передатчика — любой телефон с FM-радио; камеры — просмотр записанного файла.

## 7. Отладка (v1 — CLI, не IDE)

- `femus repl` — интерактивная консоль: подключился к плате, руками дёргаешь пины
- `femus scan` — определение платы, карта пинов, устройства на I2C-шине
- `--verbose` — весь трафик шин (каждая I2C-транзакция, каждая AT-команда)

Диагностика ошибок подключения: `scan` не видит I2C-адрес → перепутаны SDA/SCL; модем молчит на AT → не та скорость порта.

Фаза 2: веб-дашборд на localhost (живые графики, состояние пинов, ручное управление). Свой редактор/IDE не делаем.

## 8. Структура репозитория

Монорепо, один composer-пакет на старте (резать на под-пакеты — когда появятся пользователи), но с границами будущих пакетов:

```
src/Contracts/          интерфейсы портов и Board
src/Runtime/            event loop
src/Adapter/Firmata/    FirmataBoard, парсер протокола
src/Adapter/Linux/      LinuxBoard, FFI-биндинги
src/Adapter/Fake/       FakeBoard, записанные диалоги
src/Device/             драйверы устройств
src/Gsm/                AtChannel, GsmModem
bin/femus               CLI (repl, scan, test:hardware)
firmware/               модуль HX711 для ConfigurableFirmata (C++)
docs/devices/           схемы подключения модулей
examples/               по примеру на устройство
```

## 9. Тестирование

- **Pest**: юнит-тесты драйверов против FakeBoard с записанными диалогами
- Протокольные тесты Firmata-парсера и AT-парсера на реальных транскриптах
- Интеграционные прогоны на живом железе — `femus test:hardware` по чеклисту (коробка модулей владельца = полигон)

## 10. Roadmap (после v1)

- **Фаза 2:** веб-дашборд; пакет `femus/bridge` — MQTT + Home Assistant discovery (устройства сами появляются в умном доме); Bluetooth через BlueZ/D-Bus; интеграция php-wifi (сканирование/подключение к сетям)
- **Фаза 3:** больше драйверов (ультразвук, энкодер, клавиатура, DHT, DS1307, 433 МГц-протоколы, ИК-пульты), SPI-дисплеи, GPS
- Прочее: под-пакеты composer, PECL-независимые альтернативные лупы (Revolt), поддержка других одноплатников (Orange Pi, Banana Pi — тот же libgpiod)

## Вычеркнуто (осознанные отказы)

- **Компилятор PHP → C для Arduino** — исследовательский проект дороже всего фреймворка; не нужен для цели («разработчик пишет PHP и сразу видит результат» — обеспечено Firmata- и Linux-адаптерами); убивает цикл разработки (компиляция+прошивка вместо перезапуска скрипта). Автономная голая Arduino — за горизонтом; если понадобится, путь — генерация конфигурации/скетча, не компилятор.
- **Swoole как обязательная зависимость** — C-расширение поднимает порог входа; событийного `stream_select` достаточно для сенсорных нагрузок.
- **Свой IDE** — разработчики пишут в своих редакторах; наша зона — runtime-отладка.
- **OV7670 в универсальном слое** — параллельная шина неподъёмна для Arduino; камеры идут Linux-only классом через V4L2.
- **Мосты (MQTT/BT) в v1** — композиция устройств входит в v1 бесплатно (общий event loop), мосты — фаза 2, иначе v1 расползается.
