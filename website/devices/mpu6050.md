# MPU-6050 Gyroscope/Accelerometer (GY-521 module)

## Wiring to Arduino (Firmata)

| GY-521 pin | Arduino |
|------------|---------|
| VCC        | 5V      |
| GND        | GND     |
| SDA        | A4      |
| SCL        | A5      |

The address is 0x68 (0x69 if pin AD0 is pulled to power: `$board->mpu6050(0x69)`).

## Breadboard

```
      Arduino Nano
      ┌─────────┐
   5V │ ●       │
  GND │ ●       │
   A4 │ ●       │  (SDA)
   A5 │ ●       │  (SCL)
      └─────────┘
        │   │   │   │
        │   │   │   └── A5 (SCL) ── GY-521 SCL
        │   │   └─────── A4 (SDA) ── GY-521 SDA
        │   └─────────── GND rail (blue) ── GY-521 GND
        └─────────────── 5V rail (red)  ── GY-521 VCC

  Leave AD0 unconnected (or tie to GND) for address 0x68.
  Tie AD0 to the 5V rail for address 0x69.
  XDA / XCL / INT pins are unused by femus (leave them floating).
```

Resistors: none needed — the GY-521 module has onboard decoupling capacitors
and I²C pull-up resistors; external pull-ups will overdrive the bus.

**Common mistakes**

1. Swapping SDA (A4) and SCL (A5) — identical to the [LCD1602](/devices/lcd1602)
   wiring; the I²C scan will find no device; swap the two wires and retry.
2. Powering from 3.3V — some GY-521 boards have an onboard 3.3V regulator
   and expect 5V on VCC; supplying 3.3V directly may give unstable readings
   or prevent the MPU-6050 from starting.
3. Leaving INT connected without a handler — the interrupt pin will float and
   may toggle, generating spurious events; leave INT unconnected unless you
   use interrupt-driven reads.

## Code

```php
$mpu = $board->mpu6050();
$a = $mpu->readAccel();   // ['x' => g, 'y' => g, 'z' => g]
$g = $mpu->readGyro();    // ['x' => °/s, ...]
$t = $mpu->readTemperature();
```

Board lying flat on a table → z ≈ +1.0g, x and y ≈ 0.

## Verification

`php examples/gyro-dump.php <port>` — tilt the board and the axis values change.
See [`examples/gyro-dump.php`](https://github.com/femus/femus/blob/main/examples/gyro-dump.php).
